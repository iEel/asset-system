# UI/UX Design System and Adaptive Interface Guide

This is the developer-facing index for applying the Asset Management System design across Desktop and Mobile. It links to canonical policy and focused route decisions without duplicating their full contents. [`DESIGN.md`](../DESIGN.md) owns the canonical visual identity, tokens, component vocabulary, accessibility principles, and Adaptive UI policy.

## Source of Truth

1. Business workflow, RBAC, SOD, lifecycle, and security requirements.
2. [`DESIGN.md`](../DESIGN.md) for current visual and Adaptive UI policy.
3. The latest approved focused specification for a route or workflow.
4. This operational index for implementation navigation and shared behavior.
5. Older plans, Handoff history, and the original enterprise UI/UX baseline.

## Adaptive Presentation

| Concern | Desktop Management / Review | Mobile Field Operation |
|---|---|---|
| Navigation | The navy menu with sections beside the topbar on the chrome color, in the light or the dark theme | Field navigation on navigation routes; hidden in focus-task routes |
| Asset Register | Dense table, presets, columns, bulk actions | Search-first cards, compact filters, touch-safe row actions |
| Asset Detail | Comparison, history, documents, review actions | Compact identity, collapsible sections, contextual quick actions |
| Audit | Round setup, pending review, findings, close readiness | Scanner-first counting, evidence, pending queue, recent scans |
| Maintenance and Disposal | Queue management, approvals, bulk processing | Cards, explicit selection mode, focused dialogs |
| Reports | Dense filters, preview, export | Summary-first filters and contained tables |

Both presentations reuse the same URL, API, business records, workflow records, permission checks, validation, audit trail, and data model; only hierarchy and interaction may change.

## Navigation and Action Surfaces

- Navigation routes show Mobile Field Navigation.
- Scanner, edit, transaction, and detail routes with page-owned bottom actions use Focus Task Mode, and so do the settings page and every `new` and `[id]/edit` form (phase 2C). List pages keep Mobile Field Navigation.
- Only one fixed bottom region may exist at a time.
- Reserve safe-area-aware content spacing only for the active bar: the dashboard shell reserves it for Mobile Field Navigation, and a page pads its own root only when it renders its own `ActionBar`, with `actionBarPagePadding` (the four focus-task pages `/assets/[id]`, `/audit/rounds/[id]`, `/maintenance/[id]` and `/disposal/[id]`; guard LP1).
- The page frame (the `PageHeader` row, the words of the back button, the page's own action bar) switches at `md`; the shell (sidebar, Mobile Field Navigation and its space) switches at `lg`. Check every changed page at 768 and 1024px, where the row header and the field navigation show together.
- `Mark Not Found` belongs to Audit Pending, not successful scan results.
- Manual Asset Tag/Serial entry remains available beside QR scanning.

## Shared Visual and Interaction Reminders

Follow the canonical [`Colors`](../DESIGN.md#2-colors), [`Typography`](../DESIGN.md#3-typography), and [`Components`](../DESIGN.md#5-components) sections of [`DESIGN.md`](../DESIGN.md); do not copy mutable token values into route documentation. Both themes come from the same tokens (The Two-Theme Rule in [`DESIGN.md` §2](../DESIGN.md#2-colors)): never write a `dark:` class or a color for one theme, and check a change in light and dark. Use semantic statuses with readable text plus icons, shapes, or clear workflow context where useful. Reuse Lucide icons and existing component helpers, favor borders and tonal hierarchy, and avoid decorative gradients, glass effects, and heavy motion. Implement consistent loading, empty, error, and denied states.

## Shared Components

Build screens from the shared primitives in `src/components/ui/`. Their look and rules live in [`DESIGN.md` §5](../DESIGN.md#5-components); do not copy their class strings into pages.

| Need | Use | Remember |
| --- | --- | --- |
| A button, or a link that looks like one | `Button`, or `buttonVariants({ variant, size })` on a `Link` | `danger` for a destructive action in a page, `destructive` only to confirm it in a dialog; `busy={x}` while working, never with `x` in `disabled` and never with `asChild`; the label stays the same while busy; the primary action comes last; no size is 36px from `md`, `md` in a `PageHeader`, `lg` / `icon-lg` (40px) only beside a 40px field; a prerequisite gate is `aria-disabled` with `aria-describedby` to its visible reason, and its handler returns first (a rule about what the person typed is no gate); a raw `<button>` only in a shared part or an `EXEMPT` row, never a height of its own at `sm:` and never `disabled:opacity-*` (guards, spec 2D §5.4) |
| A choice of 2 to 4 options shown as buttons | `Segmented` | `aria-label` names the group; values are strings |
| A text link | `linkVariants({ size })` | `meta` when it stands alone, `inherit` inside a sentence; a stand-alone link or a drill-down count adds `inline-flex min-h-11 items-center md:min-h-0`, and a zero count is plain text |
| A text field, select or textarea | `Input`, `NativeSelect`, `Textarea` with `fieldSize` | `getFieldControlClasses()` for a control that cannot use them |
| A label with hint and error | `Field` | sets `id`, `aria-describedby`, `aria-invalid` and `aria-required`; keep `required`, `maxLength` and `minLength` on the control; `labelAction` for one icon button beside the label; never around `SearchableSelect`, never inside a `<label>`; a field and its hint follow the warning `Notice` that explains them, never sit on its fill; a field repeated in every card of a list adds `aria-describedby` with its card's name (K20); `error` from the form's `useFieldErrors`; `liveError` takes only the text of a check that runs while typing (`null` while it finds nothing), never a save's error |
| A label for a group of checkboxes or radios | `FieldGroup` (legend, hint, one error under the group, focus to its first control); a group with no rule may stay a `<fieldset className="min-w-0">` with `<legend className={cn(fieldLabelClasses, "mb-1.5")}>` | `required` on `FieldGroup`, or `<FieldRequiredMark />` in a hand-written legend |
| A radio or checkbox option | `ChoiceCard` (full-width card) or `ChoiceChip` (inline chip) | the input stays visible; Enter never submits the form |
| A file picker | `FileDropzone`, plus `FileQueueList` for files that wait to upload | help text goes in `description`, not in `Field`'s `hint` |
| A search box | `SearchField` | `onClear` and `clearLabel` only from a client component |
| A searchable picker | `SearchableSelect` | has its own label, hint and error; pass `id` and `error` so a save can focus it and tie its error (its button trigger takes no `aria-invalid`) |
| An action menu | `DropdownMenu` | an item that cannot run now uses `unavailable` with `DropdownMenuItemDescription` for the reason |
| A keyboard hint | `Kbd` | Latin keys and symbols only |
| A status | `StatusBadge` | one size; there is no `size` prop; an asset state takes its tone from `status.name` (`getAssetStateTone`), never a database color; an active record is `tone="success"` |
| A name: a role, a scope, an approver, a module | `Chip` | neutral, no tone and no marker; a state is a `StatusBadge`; a code inside is a `tag` |
| A breadcrumb trail | `Breadcrumbs` | `code: true` for an asset tag or document number |
| A page title, its facts and its buttons | `PageHeader` | the only `h1`; a status badge only in `meta`; `md` buttons, back first and primary last; no outer margin (a `space-y-6` root, or `className="mb-6"` in a form) |
| A back button in a header | `PageBackLink` through `PageHeader back` | `href` is the page's own expression, `returnTo` included; `label` is the page's own words; an icon button below `md` |
| Tabs that change the URL | `TabNav` | `aria-label` names the row; counts through `formatCount`; state that does not change the URL uses `Segmented`; a row that must keep its own scroll stays a small client wrapper that passes `ref`, `onScroll` and `linkClassName` (the asset views, the report views); a client page may cancel the navigation in `onSelect` and switch in place (the settings tabs) |
| A list table | `DataTable` with `DataTableHeader`, `DataTableHead`, `DataTableBody`, `DataTableRow` (or `ClickableTableRow`) and `DataTableCell` | one density; the first and last columns keep 16/20px; `sort` on `DataTableHead` sets `aria-sort`; `scrollHint` when the table can overflow on phones |
| An empty table | `TableEmptyRow` | one line through `children`, or `emptyState` for a title, a description or a button |
| Page links under a table | `Pagination` in `DataTable footer`, with `parseListPage`, `listPageWindow`, `lastListPage` and `appendListPage` (`src/lib/list-pagination.ts`) | 25/50/100; a page past the end redirects to `lastListPage` (a list cut in memory clamps instead); links keep `page` and `pageSize`, and so does the `returnTo` of each record link; counts above the list cover every page |
| A filter select | `FilterSelect` | `fieldSize="lg"` in a filter panel, `md` with `hideLabel` in a toolbar; `allLabel` for the "all" option |
| The buttons of a filter form | `FilterFormActions` | pass `clear` only while a filter is active |
| The active filters | `FilterChipList` | chips only for filters that are not visible on screen; `removeLabel` starts each chip's name |
| A next step and more actions in a table row | `RowActions` | data-only props; delete through `deleteAction`, never a delete button in the row; `menuLabel={tCommon("moreActionsFor", { code })}`; to open a 2C dialog, a small client wrapper renders the dialog's button outside the menu with `hideTrigger`, calls its `open()` handle and passes `returnFocusRef={openerRef}`; a dialog without a handle keeps its button in the cell |
| Counts above a list, a report or a work queue | `StatStrip` (the only number tile; `MetricCard` is gone) | values already formatted and counted over the whole filtered list; a foot wraps to two lines at most, then ends in an ellipsis (`footTitle` holds the whole text); no tone fill; a cell that filters takes `href`, the cell of the filter in use `current`, and a count that needs action `attention`; money one tile a row below `sm`, and more than four numbers in strips of at most four (`splitStatRows`; five two-digit counts may share one strip) |
| Label and value pairs | `KeyValueList` | one list per group of facts on a detail page; empty values become `Nil` by themselves (`nilLabel` when the empty value needs its own name); `null` for a missing date; a code with its name as `tag`; the facts of a phone card too (no local `MobileField` or `DocumentFact`) |
| A panel with a head row | `ContentPanel divided`, with `flush` for a table or a `ContentPanelRows` list | without `divided` it is the plain panel; a `<form>`, `<details>` or grid card that cannot be one takes `cn(getPanelClasses(), "p-4 sm:p-5")`; no frame inside a frame |
| An uploaded photo, logo or attachment image | `bg-image-stage` on the image element | the fixed light stage in both themes; on the image, not on its frame, whose placeholder icon follows the theme; `tests/dark-mode-p.test.ts` holds every image |
| Paper that must stay light in the dark theme | `data-theme="light"` on the paper element | only the A4 documents, the label sheet, its settings sample and the signature canvas; a new one adds its file to `LIGHT_SCOPES` in `tests/dark-mode-p.test.ts` with a ruling |
| An empty value | `Nil`, `orNil` | `0` is a value, not blank |
| A count or an amount of money | `formatCount`, `formatMoney` (`src/lib/display-format.ts`) | always th-TH and 2 decimals for money; the unit (`common.baht`) goes after the number, or in the column header of a table |
| A toast | `toast.*` or `useApiError().toast` | `AppToaster` styles every toast; do not pass `richColors`; never for a field's error (guard V3), only for what no field can show |
| A message box | `Notice` with `tone` | write `role` or `aria-live` at the call site |
| An empty state | `EmptyNote` for one line, `ActionEmptyState` for a title, description or action | |
| A loading state for a route | one export of `src/components/ui/page-skeleton.tsx`, rendered alone by the route's `loading.tsx` | the shape of its page at full width; a change to the page's shape changes its skeleton in the same commit |
| A dialog | `AccessibleDialog` with `AccessibleDialogBody`, `AccessibleDialogFooter` and `AccessibleDialogCancel` | a `<form className={accessibleDialogFormClasses}>` wraps body and footer; secondary first, primary last; no `<form>` in a dialog that renders inside another form; a field's error shows under its field in the dialog, and an error of the dialog's own action that names no field shows in its body as `Notice tone="danger" role="alert"`, not on the page behind it; the X comes first in the Tab order and focus opens on the first control (`focusFirstContentControl`) |
| A confirmation | `useConfirm()` | `confirmLabel` is a verb, never "ยืนยัน" (a test checks every call); `tone: "destructive"` for a delete, whose toast then says "ลบแล้ว"; it opens the one `AlertDialog`, which has the dialog look and no X |
| A save bar for a long form | `StickyFormFooter` | the last child of the `<form>`; on focus-task routes only |
| A phone action bar on a detail page | `ActionBar`, with `actionBarPagePadding` on the page root | `label={tCommon("actions")}`; up to 4 links, or 3 under a `primaryAction` (beside it on a short screen, `max-height: 32rem`); a link is primary only through its `primary` flag; the bar and the root padding change in the same commit; below `md` only |
| Progress through a multi-step flow | `Steps`, with `getLinearStepStates` (`src/lib/step-states.ts`) | numbered sections that are not steps use `FormSection` |
| A numbered form section | `FormSection` | `as="h3"` under a page that already has an `h2` |
| The record a form is about | `FormContextBanner` | `code` shows a record code as `tag` |
| A form's errors | `useFieldErrors`, a module-level `validate()` with the helpers of `src/lib/validation-rules.ts`, and `noValidate` right after `onSubmit` | errors under the field after save, the first wrong field focused (`reveal` for a tab, a `<details>`, a dialog or a step), the server's `fieldErrors` on the same fields, no validation toast, one announcement per save ([`DESIGN.md`](../DESIGN.md) **Forms: Errors Under the Field**) |

Phase 2A built the first set, phase 2C plan 1 added the form and dialog pieces (and plan 5 `ActionBar`), phase 2B plan 1 the list and page-frame pieces and phase 2D plan 2 `Chip`; phases 2B, 2C and 2D moved every screen in `src` onto them. The guards in `tests/visual-foundation-guards.test.ts`, for forms and dialogs `tests/form-migration-guards.test.ts`, and for list pages and page frames `tests/list-frame-guards.test.ts` read all of `src` and hold what may stay since plan 2D-5: each rule allows only the shared parts that own its pattern (`OWNERS`) and the sites of its `EXEMPT` list, where a row gives the file, the exact count, `why`, `ruling` and its kind, `permanent` or `phase 3` (spec 2D §5.1, checked by `exemptProblems` in `tests/helpers/guard-exempt.ts`). A count above or below its row fails, so the commit that moves a site lowers or deletes its row, and a test lists the `phase 3` rows that phase 3 must clear. Five guards of plan 2D-5 (spec 2D §5.4) keep raw colors, dashed borders outside the shared parts, raw `<button>`s, faded disabled controls and button heights at `sm:` out of `src`, apart from their `EXEMPT` rows.

`tests/validation-guards.test.ts` holds the V track (spec `2026-10-17-v-track-field-errors-design.md`) for every form a person submits: V1 lists them in `V_SCOPE` (51 forms in 44 files), and every file of `V_FORMS`, which equals `V_SCOPE`, checks itself with `noValidate` right after `onSubmit` and a `validate(` (V2), shows no `toast.error` or `toast.warning` outside a `catch` but the after-save results of `NON_VALIDATION_TOASTS` (V3), and gives every required select an `id` and an error (V4; `SELECT_STAR_ONLY` is empty, V5). It is not an `EXEMPT` guard: a new form joins both lists in the commit that adds it.

## UI QA Checklist

- Verify 375px, 390px, 414px, 768px, and desktop viewports.
- Check light and dark, and with no choice the OS emulated both ways; print preview stays light, and paper keeps its colors.
- Confirm no body-level horizontal overflow.
- Confirm exactly one bottom navigation or action region is active.
- Confirm 44px mobile targets and safe-area padding for the active fixed region.
- Test keyboard focus, Escape behavior, focus restoration, and accessible names.
- Check Thai/English parity and wrapping for long Thai text.
- Confirm every status combines text with semantic color, icon, or shape.
- Test loading, empty, error, denied, offline, and partial-failure states.
- Save each form empty and with a wrong value: no browser bubble and no toast; the first wrong field takes focus (on its tab, in its section or step) with its error under it, read once; a button that waits stays focusable and reads its reason.
- Where applicable, complete real Android/iPhone UAT for camera access, torch/zoom, rotation, offline queue, evidence upload, and the Brother print dialog.
