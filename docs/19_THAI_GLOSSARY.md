# คำศัพท์ไทยกลาง

คำที่ใช้กับข้อความไทยทั้งระบบ (ที่มา: `docs/superpowers/specs/2026-10-08-thai-copy-cleanup-design.md` ข้อ 2)

### 2.1 คำหลัก

| เรื่อง | ใช้ | เลิกใช้ |
|---|---|---|
| ที่ที่ทรัพย์สินอยู่ | **ที่ตั้ง** · เมนูข้อมูลหลัก "ที่ตั้ง" · ข้อไม่ตรง "ที่ตั้งไม่ตรง" | พื้นที่ · พื้นที่/ตำแหน่ง · Location |
| ผลตรวจที่ไม่ตรงระบบ | **รายการไม่ตรง** | Finding · ข้อมูลไม่ตรง (เมื่อหมายถึงรายการ) |
| ดูแล้วตัดสินอนุมัติ/ปฏิเสธ | **พิจารณา** · รอพิจารณา · พิจารณาแล้ว | Review · ตรวจทาน |
| ให้ใช้ชั่วคราวแล้วต้องคืน | **ยืมใช้ชั่วคราว** · สถานะ **ถูกยืม** | เบิกใช้งานชั่วคราว · ถูกเบิก |
| ให้ใช้ถาวร | **ส่งมอบ** | — |
| เอาของออกจากคลัง | **เบิกจากคลัง** | — |
| รับของกลับ | **รับคืน** | — |
| รหัสบนตัวทรัพย์สิน | **รหัสทรัพย์สิน** | Asset Tag · Tag |
| ขอบเขตรอบตรวจ | **ขอบเขต** · **นอกขอบเขต** | Scope · นอก Scope |
| รอบตรวจ | **ตรวจนับ** | Audit |
| ประวัติการแก้ | **ประวัติการแก้ไข** | Audit Trail |
| ผู้ใช้ทรัพย์สิน | **ผู้ถือครอง** | ผู้ครอบครอง · ผู้ถือ (เขียนย่อ) |
| หมวด | **หมวดหมู่** ("ประเภท" ใช้กับชนิด เช่น ประเภทการถือครอง ประเภทรายการไม่ตรง) | หมวด (เขียนย่อ) |
| ทรัพย์สินออกจากบัญชี | **ตัดจำหน่าย** ("จำหน่าย/ขาย/บริจาค/ทำลาย" ใช้เมื่อเป็นวิธี) | — |
| เมนูส่งออกและนำเข้าที่หัวหน้าทะเบียนทรัพย์สิน | **ส่งออก / นำเข้า** (ส่งออกก่อน) · รายการในเมนู "ส่งออกตามตัวกรอง (N รายการ)" "ดาวน์โหลดแม่แบบ" "นำเข้าจาก Excel" | นำเข้า / ส่งออก · Export / Import · ปุ่มส่งออกและนำเข้าแยกกัน |
| ชุดตัวกรองที่ตั้งชื่อเก็บไว้ในหน้าทะเบียนทรัพย์สิน | **มุมมองที่บันทึกไว้** · ปุ่ม "บันทึกมุมมองนี้" | Saved view · ตัวกรองที่บันทึก |
| การ์ดแรกของฟอร์มเพิ่มทรัพย์สินที่รวมช่องที่ต้องกรอกก่อนบันทึก | **ข้อมูลที่ต้องกรอก** · ตัวนับ "กรอกแล้ว n จาก m ช่องที่ต้องกรอก" · ส่วนที่พับไว้ "กรอกแล้ว n จาก m ช่อง" | ข้อมูลบังคับ · Required |
| แถวท้ายฟอร์มที่บอกช่องที่ต้องกรอกที่ยังว่าง | **ยังขาด n ช่องที่ต้องกรอก · <ชื่อช่อง>** · ปุ่ม "ไปช่องแรกที่ยังขาด" | ยังไม่ครบ n ช่อง · กรอกไม่ครบ |
| แก้ค่าที่บันทึกผิดไว้ในทะเบียน (ที่ตั้ง ผู้ถือครอง แผนก) ไม่ใช่การย้ายจริง | **แก้ไขข้อมูล…** · ประวัติ "แก้ไขข้อมูลที่ตั้ง" "แก้ไขข้อมูลผู้ถือครอง" "แก้ไขข้อมูลแผนก" · ช่อง "เหตุผลที่แก้" · "เปลี่ยน…" ใช้กับการย้ายหรือเปลี่ยนผู้ถือครองจริง (ส่งมอบ รับคืน โอนย้าย) | แก้ข้อมูล (คำพูด) · "เปลี่ยน…" เมื่อหมายถึงแก้ที่บันทึกผิด |
| เปลี่ยนรหัสทรัพย์สินจริงในหน้าแก้ไข (ป้ายที่พิมพ์ไว้ยังแสดงรหัสเดิม) ไม่ใช่การแก้ข้อมูลที่บันทึกผิด | **เปลี่ยนรหัส** · ชื่อหน้าต่างและประวัติ "เปลี่ยนรหัสทรัพย์สิน" · ช่อง "รหัสใหม่" · ปุ่ม "ใช้รหัสนี้" | แก้ไขรหัส · แก้ไขข้อมูลรหัส |
| หัวการ์ดแรกของหน้าแก้ไขทรัพย์สิน และปุ่มบันทึกของหน้านั้น | **ข้อมูลหลัก** · ปุ่ม "บันทึกการแก้ไข" (หน้าเพิ่มใช้ "บันทึก") | — |

### 2.2 ศัพท์อังกฤษที่แปล

| เดิม | ใหม่ | เดิม | ใหม่ |
|---|---|---|---|
| Label | ป้าย (ป้าย QR) | Template | แม่แบบ |
| Prefix | คำนำหน้ารหัส | workflow | ขั้นตอนงาน |
| Checklist | รายการตรวจ | action plan | แผนแก้ไข |
| Preview | ตัวอย่าง | Filter | ตัวกรอง |
| Role | บทบาท | Timeline | ลำดับเหตุการณ์ |
| Lifecycle | วงจรทรัพย์สิน | Running number | เลขลำดับ |
| Sync | ซิงก์ (ซิงก์ข้อมูลจาก AD) | Retention | ระยะเวลาเก็บ |

### 2.3 คงไว้

- ชื่อเฉพาะและคำที่พนักงานใช้อยู่แล้ว: LDAP · AD · QR · PDF · Excel · CSV · URL · API · Serial · License (เขียนแบบนี้ทุกที่ ไม่ใช้ "ไลเซนส์") · PM (หัวข้อเขียนเต็ม "บำรุงรักษาตามรอบ (PM)")
- หน้าผู้ดูแลระบบ (ตั้งค่า LDAP · Integration API · บันทึกระบบ) ใช้ศัพท์เทคนิคได้ เช่น Token · Client ID · JSON — แก้เฉพาะจุดที่มีคำไทยใช้ทั่วไป (เช่น ตัวกรอง ตัวอย่าง)
- ภาษาอังกฤษ (`messages/en.json`): ให้ key ตรงกับไทยเสมอ และแก้คำในความหมายเดียวกัน (Finding → Discrepancy · Review → Decision) ไม่ขัดเกลาทั้งไฟล์

## ใช้อย่างไร

- เขียนข้อความไทยใหม่ใช้คำในตารางเสมอ · `tests/thai-glossary.test.ts` ตรวจคำเลิกใช้ในทุกหมวดของ `messages/th.json`
- แก้ไฟล์ข้อความด้วย `node scripts/messages-edit.mjs <changes.json>` (รูปแบบไฟล์อยู่ในหัวสคริปต์) ไม่แก้ JSON ด้วยมือทั้งไฟล์
- ข้อยกเว้นเฉพาะ key ใส่ใน `keyExceptions` ของ test พร้อมเหตุผล
- ปีในหน้าไทยเป็น พ.ศ. (`src/lib/display-year.ts`) ยกเว้นรหัสที่มีปีในตัว
- error จากเซิร์ฟเวอร์แปลที่ `src/lib/api-error-catalog.ts` (เพิ่ม error ใหม่ใน API ต้องเพิ่มคำแปลด้วย test จึงจะผ่าน) · หน้าจอแสดงคำไทยก่อนและข้อความเดิมเป็นบรรทัดเล็กใต้ (`useApiError` / `ApiErrorText`)
- error ที่ไม่ได้ตั้งใจโยน (ฐานข้อมูล ไฟล์ บั๊ก) ไม่ส่งข้อความจริงให้ผู้ใช้ — ได้ "Unexpected error · ref xxxxxxxx" และ log ฝั่งเซิร์ฟเวอร์มี ref เดียวกัน (`src/lib/api-error-exposure.ts`) · ข้อความที่ตั้งใจให้ผู้ใช้เห็นต้องโยนเป็น `Error` ไม่ใช่ `TypeError`/`RangeError`
- รหัสสถานะจากฐานข้อมูล (เช่น `scanned`, `reviewed`) แสดงผ่านคำแปลเสมอ (`src/lib/audit-item-status-labels.ts`) · รหัสที่ยังไม่มีคำแปลแสดงตามจริง ไม่ซ่อน
