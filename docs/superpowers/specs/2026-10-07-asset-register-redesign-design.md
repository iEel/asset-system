## 1. เป้าหมายและหลักฐาน

**ผู้ใช้สั่ง:** ทำส่วน B ต่อ เรียง ทะเบียน → สแกน → ภาษา · งานหลักบนหน้าทะเบียน = **หาเครื่องเฉพาะชิ้น** รองลงมา = **ไล่ดูตามตัวกรอง** · เลือกแนวทางจากภาพตัวอย่าง (visual companion) = **แท็บสถานะพร้อมตัวเลข + ปุ่มงานถัดไปตามสถานะ + ⋯ + รูปย่อจริงฝั่ง server** · วิธีทำ = **แยกเป็นคอมโพเนนต์ย่อย ใช้ข้อมูลแบบเดิม**

**หลักฐาน** — วัดบนแอป dev (DB `asset_management_dev`) 2026-10-07 หลังส่วน A:

- 1440×900: ตัวกรองด่วน 3 กลุ่ม + ฟอร์มค้นหากินจอแรก ~70% → **เห็นแถวข้อมูล 1 แถว**
- 1440: คอลัมน์รหัส (176px) + ชื่อ (320px) ติดซ้าย · ปุ่ม 4 ปุ่ม (176px) ติดขวา · ตารางต้องการ ~1,250px แต่มี ~1,130px → **ปุ่มทับคอลัมน์ "สภาพ"** ต้องเลื่อนแนวนอน
- 375×812: ตัวกรองสูง ~600–650px · **การ์ดใบแรกเริ่มที่ 1,043px** · การ์ดละ **457px** (~1.7 ชิ้นต่อจอ)
- รูปในตาราง: `next/image unoptimized` โหลด**ไฟล์ต้นฉบับ**จาก `/api/attachments/{id}?inline=1` ซึ่งตอบ `Cache-Control: private, no-store` · รูปรุ่น 224 รูป ขนาดกลาง 105KB (p90 325KB, สูงสุด 2MB) · รูปของทรัพย์สินเอง 7 รูป ขนาดกลาง 2.1MB · หน้าเดียวโหลดรูป ~1–3MB ทุกครั้งที่เปิด
- ตัวเลือกคอลัมน์เป็น `<details>` (คลิกข้างนอกไม่ปิด) · หน้านี้ยังมี `StatusPill` ของตัวเอง (`asset-register-table.tsx:1013`) · การแบ่งหน้าเป็นแบบที่ 5 ของแอป

**สำเร็จเมื่อ**

1. 1440×900: จอแรกเห็น **≥ 8 แถว** และไม่มีสิ่งใดทับคอลัมน์สถานะ/สภาพ (ชุดคอลัมน์ค่าเริ่ม ไม่ต้องเลื่อนแนวนอน)
2. 375×812: แถวแรกเริ่มในจอแรก และเห็น **≥ 5 แถว**
3. งานที่ทำได้วันนี้ยังทำได้ครบ: ตัวกรองทุกตัว · เรียงลำดับ · ชุดคอลัมน์ · เลือกหลายแถว + พิมพ์ Label / ย้ายที่ตั้ง-ผู้ถือ / ส่งออก · ธุรกรรมต่อแถว · คัดลอก · ลบ · จำมุมมองและตำแหน่งเลื่อน · ตัวช่วยนำเข้า
4. รูปย่อในตาราง **< 10KB ต่อรูป** และเบราว์เซอร์ cache ได้
5. `npm run verify` ผ่าน · ตรวจบนแอป dev ตามข้อ 7

**นอกขอบเขต** — การแบ่งหน้าของหน้าอื่น · รูปย่อในหน้ารายละเอียด/ทรัพย์สินของฉัน · ตัวเลขสดบนปุ่มในแผงตัวกรอง · cache รูปย่อบนดิสก์ · สแกนตรวจนับ (B2) · เก็บศัพท์ไทยทั้งแอป (B3 — ข้อความใหม่ใน B1 เขียนเป็นไทย) · ไม่มี migration DB

## 2. แนวทางที่เลือก

**แยกคอมโพเนนต์ ใช้ข้อมูลเดิม:** ยังดึงข้อมูลฝั่ง server ใน `assets/page.tsx` · ตัวกรองยังเป็น URL param เดิม (`src/lib/asset-list-query.ts`) จึงคงลิงก์เดิม การจำมุมมอง (`asset-register-view-memory`) และปุ่มย้อนกลับ · แตก `asset-register-table.tsx` (1,079 บรรทัด) และส่วนตัวกรองของ `page.tsx` (974 บรรทัด) เป็นคอมโพเนนต์ที่มีหน้าที่เดียว · เพิ่ม query นับต่อสถานะ 1 ตัว และ API รูปย่อ 1 ตัว

ไม่เลือก: ตารางฝั่ง client + API (รื้อการดึงข้อมูล/สิทธิ์/มุมมองที่จำ — เสี่ยงเกินประโยชน์) · แก้ CSS บนโครงเดิม (ได้ไม่ครบตามภาพ ไฟล์ใหญ่ยังอยู่)

## 3. เลย์เอาต์และตัวกรอง

### 3.1 ส่วนบน

- หัวหน้า: `MasterDataHeader` เดิม (ชื่อ · คำอธิบายสั้น · "+ เพิ่มทรัพย์สิน")
- **แถบค้นหา** (การ์ดเดียว):
  - desktop (md+): `ค้นหา` (กว้างสุด, placeholder "ค้นหา รหัส · ชื่อ · Serial · ผู้ถือครอง · ที่ตั้ง") · `บริษัท` · `สาขา` · `หมวดหมู่` · ปุ่ม "⚙ ตัวกรองเพิ่มเติม" มีตัวเลขจำนวนตัวกรองในแผงที่ใช้อยู่ — แถวเดียว (ที่ md–lg อนุญาตขึ้น 2 แถว)
  - มือถือ: `ค้นหา` + ปุ่ม ⚙ (ตัวเลขนับรวม บริษัท/สาขา/หมวดหมู่ด้วย) · ติดบนสุดของรายการขณะเลื่อน
  - ส่งเป็น GET form ไป `/{locale}/assets` เหมือนเดิม: ช่องค้นหาส่งเมื่อกด Enter หรือปุ่มแว่นขยายในช่อง (`aria-label` "ค้นหา") · select บริษัท/สาขา/หมวดหมู่ **ส่งทันทีเมื่อเปลี่ยนค่า** (`form.requestSubmit()` ฝั่ง client — รายการสาขาจึงกรองตามบริษัทที่เลือกได้ทันทีเหมือนเดิมที่ต้องกด "กรอง") · เอาปุ่ม "กรอง" แยกออก

### 3.2 แท็บสถานะ

- แท็บ: **ทั้งหมด · พร้อมใช้งาน · ใช้งานอยู่ · ถูกเบิก · รอซ่อม · อยู่ระหว่างซ่อม** — ป้ายจาก i18n key เดิม `asset.quickFilterAll`, `quickFilterReady`, `quickFilterInUse`, `quickFilterCheckedOut`, `quickFilterPendingRepair`, `quickFilterUnderMaintenance` · จับคู่สถานะด้วย `AssetStatus.name` = `Ready`, `In Use`, `Checked Out`, `Pending Repair`, `Under Maintenance` (แบบเดียวกับตัวกรองด่วนเดิม `page.tsx:563-567`) · สถานะที่ไม่มีใน DB → ไม่แสดงแท็บนั้น
- แต่ละแท็บเป็น `<Link>` ที่ตั้ง `statusId` (ทั้งหมด = ลบ `statusId`) **โดยคงพารามิเตอร์อื่นไว้** และกลับไปหน้า 1
- **ตัวเลข:** นับด้วย `prisma.asset.groupBy({ by: ["statusId"], where: <where เดียวกับตาราง แต่ไม่มีเงื่อนไข statusId>, _count: { _all: true } })` · "ทั้งหมด" = ผลรวม · ใช้ตัวกรองอื่นทั้งหมดรวม crossScope
- แท็บที่เลือก = แท็บที่ `statusId` ตรง · ไม่มี `statusId` → "ทั้งหมด" · `statusId` เป็นสถานะที่ไม่มีแท็บ → ไม่มีแท็บเลือก และขึ้นชิปสถานะ (3.4)
- desktop: แถบแท็บใต้แถบค้นหา · มือถือ: ชิปเลื่อนแนวนอน
- **เปลี่ยนจากเดิม:** ตัวกรองด่วนเดิมล้างกันเอง (กดสถานะแล้ว `dataQuality`/`crossScope` หาย) — ของใหม่ **ใช้ร่วมกันได้** (เงื่อนไข AND ที่ `buildAssetWhere` รองรับอยู่แล้ว)

### 3.3 แผง ⚙ ตัวกรองเพิ่มเติม

- `Sheet` ของส่วน A: desktop `side="right"` · มือถือ `side="bottom"` (สูงไม่เกิน 85dvh เลื่อนภายใน)
- เนื้อหา (GET form เดียว ปุ่มท้ายแผง "ล้าง" = ลิงก์ล้างตัวกรองในแผง · "แสดงผล" = submit):
  - มือถือเท่านั้น: บริษัท · สาขา · หมวดหมู่
  - สถานะ (select ทุกสถานะ — สำหรับสถานะที่ไม่มีแท็บ) · สภาพ · ประเภทการถือครอง (พร้อมตัวช่วยคำอธิบายเดิม)
  - ข้อมูลที่ต้องตรวจ (`dataQuality` เลือกได้ 1): ไม่มี Serial · ไม่มีรูป · ข้อมูลซื้อไม่ครบ · ใกล้หมดประกัน · ผู้รับผิดชอบไม่ครบ · แผนกไม่ครบ (key ใหม่ `asset.dataQualityDepartment` = "แผนกไม่ครบ" / "Missing department" — เดิมค่านี้ไม่มีป้ายและชิปแสดงค่าดิบ)
  - ความเป็นเจ้าของ (`crossScope` เลือกได้ 1): ต่างบริษัท/ต่างสาขาทั้งหมด · ผู้ถือต่างบริษัท · ผู้ถือต่างสาขา · ที่ตั้งต่างสาขา
  - จำนวนต่อหน้า 10 / 25 / 50 / 100
  - hidden input ของพารามิเตอร์ที่ไม่มีช่องกรอก (`search`, `custodianId`, `supplierId`, `brandId`, `modelId`, `activity`, `sort`, `direction` และบน desktop `companyId`/`branchId`/`categoryId`) เพื่อไม่ให้หาย

### 3.4 ชิป แถวสรุป และส่วนท้าย

- **ชิป** (ใต้แท็บ แสดงเมื่อมี): ตัวกรองทุกตัวที่ไม่เห็นบนจอ — ทุกค่าในแผง · สถานะที่ไม่มีแท็บ · ยี่ห้อ/รุ่น · กิจกรรม · บนมือถือรวมบริษัท/สาขา/หมวดหมู่ · แต่ละชิปมี × (ลิงก์ที่ลบพารามิเตอร์นั้น) + "ล้างทั้งหมด" · ข้อมูลชิปสร้างฝั่ง server ด้วยฟังก์ชันล้วน
- **แถวสรุป:** "{from}–{to} จาก {total} รายการ" · "เรียง ▾" (DropdownMenu ของลิงก์: เพิ่มล่าสุด · เพิ่มเก่าสุด · รหัส ก→ฮ/A→Z · รหัส Z→A · ชื่อ A→Z · วันที่ซื้อล่าสุด · ราคาสูง→ต่ำ — map ไป `sort`/`direction` เดิม) · "คอลัมน์ ▾" (desktop) · "ส่งออก ▾" (desktop: ส่งออกตามตัวกรอง · ดาวน์โหลด Template) · มือถือ: ปุ่ม "เลือก" (3.6)
- ส่วนท้าย: การแบ่งหน้า (4.4) · ตัวช่วยนำเข้าเดิม (ปิดไว้ค่าเริ่ม) ใต้ตาราง

## 4. ตารางและปุ่มประจำแถว

### 4.1 คอลัมน์ desktop

ชุดค่าเริ่ม "ปฏิบัติการ" (`asset-register-columns.ts` เดิม): ☐ · รหัส · ชื่อ · ที่ตั้งปัจจุบัน · ผู้ถือครอง · สถานะ · สภาพ · การดำเนินการ

- `table-layout: fixed` ผ่าน `<colgroup>` · ความกว้าง: ☐ 44 · รหัส 172 · ชื่อ ยืดหยุ่น (ขั้นต่ำ 236) · ที่ตั้ง 140 · ผู้ถือครอง 160 · สถานะ 132 · สภาพ 96 · การดำเนินการ 150 · คอลัมน์อื่นเมื่อเปิด: หมวดหมู่ 160 · บริษัท/สาขา 120 · ประเภทการถือครอง 120 · ราคาซื้อ 120
- ตารางกว้างขั้นต่ำ = ผลรวม → เมื่อเกินพื้นที่ (ชุด "ทั้งหมด"/"บัญชี") เลื่อนแนวนอนได้ · **รหัส** `sticky left-0` · **การดำเนินการ** `sticky right-0` พร้อมเงาขอบซ้ายเมื่อมีเนื้อหาเลื่อนอยู่ข้างใต้ · ชื่อ**ไม่ติด**อีกต่อไป
- ช่องชื่อ: รูปย่อ 40px (5) · ชื่อ 1 บรรทัด `truncate` + `title` ชื่อเต็ม · Serial บรรทัดเล็ก (ไม่มี Serial → ไม่แสดงบรรทัด)
- ที่ตั้ง/ผู้ถือครอง: `truncate` + `title`
- สถานะ/สภาพ: `StatusBadge` (ส่วน A) โทนจาก `getAssetStateTone(name)` · ลบ `StatusPill` ในไฟล์นี้
- แถวสูง ~56px · หัวคอลัมน์เรียงได้ (รหัส · ชื่อ · ราคาซื้อ) เหมือนเดิม · หัวสถานะ/สภาพคงตัวช่วยคำอธิบาย
- `ClickableTableRow` เดิม (คลิก/Enter = รายละเอียด) · ช่องที่กดได้ทั้งหมดอยู่ใน `[data-no-row-click]` หรือเป็น `a`/`button`

### 4.2 ปุ่มประจำแถว

- **ปุ่มงานถัดไป** — `getRowNextAction(transactions): "checkout" | "checkin" | null` (ฟังก์ชันล้วน): `checkout` ถ้ารายการ checkout `enabled` · ไม่งั้น `checkin` ถ้า `enabled` · ไม่งั้น `null` — ข้อมูล `transactions` คือผลของ `asset-operation-policy` ที่หน้าคำนวณอยู่แล้ว · แสดงเป็นปุ่มเล็กสี primary-soft: "⇄ ส่งมอบ" / "↩ รับคืน" ลิงก์ไป `href` เดิมของ action นั้น
- **⋯** (`DropdownMenu` บน desktop · `Sheet side="bottom"` บนมือถือ — เนื้อหาเดียวกัน):
  - กลุ่ม "ธุรกรรม": ส่งมอบ · รับคืน · โอนย้าย — ข้อที่ `enabled=false` เป็น disabled พร้อมเหตุผลจาก `labels.reason` เดิม
  - แก้ไข (ตามสิทธิ์แก้ไขเดิม) · คัดลอกเป็นรายการใหม่ (`buildAssetCloneHref` เดิม ตามสิทธิ์สร้าง)
  - ลบ (`variant="destructive"`, `useDeleteAction` + `returnFocusRef` ไปที่ปุ่ม ⋯ — ส่วน A) ตามสิทธิ์ลบเดิม
  - `DropdownMenuContent`/`SheetContent` มี `data-no-row-click`
- เอาปุ่ม "ดู" ออก (คลิกแถว = รายละเอียด) · แทน `AssetRegisterTransactionMenu`/`AssetRegisterMoreMenu` และ `AssetDeleteButton` ในตาราง

### 4.3 มือถือ (< md)

- แถวละ ~80px (`<li>` ในรายการ ไม่ใช่การ์ดมีขอบ): รูปย่อ 44px · บรรทัด 1 รหัส (ตัวหนา) · บรรทัด 2 ชื่อ `truncate` · บรรทัด 3 ที่ตั้ง · `StatusBadge` สถานะ · ปุ่ม ⋯ 44×44
- ป้ายสภาพ/ประเภทการถือครองแสดงเฉพาะเมื่อ `needsFieldAttention` (กติกาเดิม `asset-register-table.tsx:1027-1029`)
- แตะแถว = รายละเอียด (ลิงก์ทั้งแถว) · ⋯ = แผงด้านล่าง (4.2) ข้อแรกคืองานถัดไปถ้ามี

### 4.4 การแบ่งหน้า

### 4.5 เลือกหลายรายการ

- desktop: ช่อง ☐ ต่อแถว + หัวตารางเลือกทั้งหน้า (เดิม) · แถบงานเป็นชุดเดิม (พิมพ์ Label · ย้ายที่ตั้ง/ผู้ถือ · ส่งออกที่เลือก · ล้าง) อยู่เหนือตาราง
- มือถือ: ปุ่ม "เลือก" ในแถวสรุปเปิด **โหมดเลือก** — แต่ละแถวแสดง ☐ แตะแถว = ติ๊ก (ไม่เปิดรายละเอียด) · ปุ่มเปลี่ยนเป็น "เสร็จ" · แถบงานเป็นชุด `fixed` เหนือเมนูล่าง (`bottom: calc(5.25rem + env(safe-area-inset-bottom))`) · ออกจากโหมด = ล้างที่เลือก
- ตรรกะเลือก/งานเป็นชุด (`selectedIds`, bulk update dialog, CSV) ย้ายมาแบบเดิม ไม่เปลี่ยนพฤติกรรม

### 4.6 ตัวเลือกคอลัมน์

## 5. รูปย่อฝั่ง server

- **API ใหม่** `GET /api/attachments/[id]/thumbnail` (`src/app/api/attachments/[id]/thumbnail/route.ts`):
  - หา attachment `isActive` · สิทธิ์เหมือน `GET /api/attachments/[id]` (`hasAttachmentPermission` / `canViewOwnAssetAttachment` / `requireAttachmentPermission`) · path ผ่าน `assertSafeUploadPath`
  - ชนิดที่ย่อได้: `image/jpeg`, `image/png`, `image/webp`, `image/gif`, `image/avif` · อื่น → **415**
  - ไฟล์ไม่มีบนดิสก์ → **404** · `sharp` อ่าน/ย่อไม่ได้ → **422**
  - `sharp(buffer).rotate().resize(96, 96, { fit: "inside", withoutEnlargement: true }).webp({ quality: 75 })` (GIF/AVIF ใช้เฟรมแรก)
  - header: `Content-Type: image/webp` · `Cache-Control: private, max-age=604800, immutable` · `ETag: "{id}-96"` · `X-Content-Type-Options: nosniff` · request ที่มี `If-None-Match` ตรง → **304** (ตรวจสิทธิ์ก่อนตอบ 304)
  - เหตุผลที่ cache ได้: ไฟล์แนบไม่ถูกแก้ในที่เดิม อัปโหลดใหม่ได้ id ใหม่ · API ไฟล์เต็มเดิมคง `no-store`
- **ตรรกะล้วน** `src/lib/attachment-thumbnail.ts`: `thumbnailableImageTypes`, `isThumbnailable(fileType)`, `buildThumbnailETag(id)`, `thumbnailCacheHeaders()`, `matchesIfNoneMatch(header, etag)` · route เป็นตัวต่อสาย
- **ฝั่งหน้าเว็บ** `src/components/assets/asset-thumbnail.tsx` (client): `<img>` (หรือ `next/image unoptimized`) จาก `/api/attachments/{id}/thumbnail` · `loading="lazy"` `decoding="async"` · `onError` → ไอคอน `ImageIcon` · ไม่มีรูป/ชนิดที่ไม่รองรับ → ไอคอน · คลิกรูป (ปุ่ม `data-no-row-click`) → `AttachmentPreviewDialog` (ส่วน A) แสดงไฟล์เต็ม `?inline=1`
- ลำดับเลือกรูปเดิม (`page.tsx:304-316`): รูปรุ่นก่อน แล้วรูปของทรัพย์สิน
- **dependency:** เพิ่ม `sharp` (`^0.34.5`, ตรงกับที่ติดมากับ Next) ใน `dependencies` · ติดตั้งด้วย `npx -y npm@10.9.4 install sharp@^0.34.5 --ignore-scripts` แล้วตรวจ `npm ci` ของ npm 10 · lockfile มี binary optional ของ linux-x64 สำหรับ Prod
