### 5.9 B4: แบ่งหน้าจริง 9 รายการ

#### 5.9.1 กติการ่วม

- **พารามิเตอร์:** `page` และ `pageSize` (ชื่อเดียวกับ master-data, disposal, maintenance, rounds/[id], ทะเบียน) · `pageSize` รับ 25 / 50 / 100 (R-k) ค่าอื่นเป็น 25 · `page` เป็นจำนวนเต็ม ≥1 ค่าอื่นเป็น 1
- **ค่าตั้งต้น 25 ทุกรายการ** (เท่ากับ `src/lib/master-data-query.ts:27`, `src/lib/asset-list-query.ts:35`, `src/lib/audit-round-result-filters.ts:101`) · URL เขียน `page` เมื่อ >1 และ `pageSize` เมื่อ ≠25 เท่านั้น ลิงก์ค่าตั้งต้นจึงเหมือนวันนี้ทุกตัวอักษร (เช่น `/th/audit/rounds?view=open` ใน `tests/audit-round-result-drilldown.test.ts:63`)
- **ตัวช่วยใหม่ (pure, ไม่มี Prisma):** `src/lib/list-pagination.ts`: `LIST_PAGE_SIZES = [25, 50, 100] as const` · `parseListPage(raw)` → `{ page, pageSize }` · `listPageWindow(state)` → `{ skip, take }` · `lastListPage(total, pageSize)` = `max(1, ceil(total / pageSize))` · `appendListPage(params: URLSearchParams, state)` เขียนเฉพาะค่าที่ไม่ใช่ค่าตั้งต้น · ช่วงแถวใช้ `paginationRange` เดิม (`src/lib/master-data-query.ts:54-63`) · ถ้าส่วน primitive กำหนดชุดขนาดหน้าไว้ ให้ `LIST_PAGE_SIZES` import จากที่นั่น
- **query:** `findMany` เพิ่ม `skip`/`take` จาก `listPageWindow` · `count({ where })` (หรือ `groupBy`) เดียวกันใน `Promise.all` เดียวกัน (ไม่เพิ่มรอบรอ) · `orderBy` เดิม + `{ id: "asc" }` ต่อท้ายให้ลำดับคงที่ข้ามหน้า (แถวที่ `createdAt` เท่ากันจะไม่ซ้ำหรือหายระหว่างหน้า)
- **หน้าเกินขอบ:** ถ้า `rows.length === 0 && total > 0 && page > lastListPage(total, pageSize)` → `redirect()` ไป URL เดิมที่ `page = lastListPage` (เกิดเมื่อลบแถวสุดท้ายของหน้าสุดท้าย เช่น "หาไม่พบ" ใน pending หรือลบข้อมูลหลัก) · ใช้กติกานี้กับทุกหน้าที่ย้ายไป `Pagination` ใน 2B ด้วย เพราะวันนี้ master-data ใช้ `skip` ที่ไม่ clamp (`D/master-data/branches/page.tsx:62`) แต่ตัวแบ่งหน้าแสดง `safePage` (`:369`) จึงเห็นตารางว่างพร้อม "หน้า 4 จาก 4"
- **ตัวกรองเปลี่ยน → กลับหน้า 1 คง `pageSize`:** ลิงก์แท็บ/ชิป และฟอร์มค้นหา (`MasterDataSearch hiddenInputs`) ส่ง `pageSize` ถ้า ≠25 และไม่ส่ง `page`
- **`returnTo`:** href "ตัวเอง" ของแต่ละรายการ (ที่ส่งเป็น `returnTo`) ต้องมี `page`/`pageSize` · ตัว normalize ทุกตัวคง `url.search` อยู่แล้ว (`src/lib/operational-return-navigation.ts:37-45`, `src/lib/master-data-return-navigation.ts:35-38`) จึงพาเลขหน้ากลับได้เองเมื่อ path ตรง
- **กล่องตัวเลขยอดเต็มยังนับยอดเต็ม:** ไม่คำนวณจากแถวของหน้า
- **เวลา query:** ห่อ `count` ของ logs, history, findings ด้วย `withPerformanceTiming` (`src/lib/performance-timing.ts:25`, แบบ `D/audit/rounds/page.tsx:85`) แล้ววัดบน dev · ถ้า count ช้า ให้บันทึกในเอกสารเป็นความเสี่ยง ห้ามเพิ่ม index ใน 2B

#### 5.9.3 หมายเหตุต่อรายการ

- **history:** ทุกแถวที่ where เดิมดึงมาเป็นรายการตัดสินเสมอ (`buildApprovalDecisionLogItems` ทิ้งเฉพาะแถวที่ `getApprovalDecision` คืน `null` `src/lib/approval-decision-log.ts:46-76` และ where `:327-337` ตรงกับตารางนั้น) จึงนับใน DB ได้ตรงกับที่แสดง · `buildSystemLogRecordLabels` (`:54`) ทำเฉพาะแถวของหน้า · พนักงานจะเห็นตัวเลขสรุปมากขึ้นเมื่อมีเกิน 150 รายการ
- **pending:** "หาไม่พบ" ทำให้แถวหายจากหน้า · ถ้าเป็นแถวสุดท้ายของหน้าสุดท้าย กติกาหน้าเกินขอบพาไปหน้าก่อน
- **findings:** "อนุมัติที่เลือก" ทำเฉพาะแถวในหน้า · ข้อความ `batchReviewHelp` เขียน "ในหน้านี้" อยู่แล้ว (`messages/th.json` `auditFinding.batchReviewHelp`) ไม่ต้องแก้
- **rounds:** ตารางช่องว่างความครอบคลุม (`CoverageGapList` `:688-765`) ไม่แบ่งหน้า
- **PM:** ลำดับในหน้าเท่ากับวันนี้ (สถานะ แล้ว `nextDueDate`) ต่างแค่ตัวตัดสินเมื่อวันเท่ากัน (`id`) · `Array.prototype.sort` ที่ใช้วันนี้ stable จึงไม่มีลำดับอื่นที่ผู้ใช้พึ่ง
- **my-assets:** query เบาไม่จำกัดจำนวนแต่ดึงแค่ชื่อสถานะกับ id รูป 1 ตัวต่อชิ้น
- **ส่งออกทุกตัว** (`/api/audit-findings/export`, `/api/maintenance-tickets/export`, `/api/disposal-requests/export`) ไม่รับ `page` และยังส่งออกทั้งชุดที่กรอง
