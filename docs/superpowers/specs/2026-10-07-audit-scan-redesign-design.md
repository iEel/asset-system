**สำเร็จเมื่อ**
1. 375×812: ช่องค้นหาและปุ่มเลือกห้องอยู่ในจอแรกโดยไม่ต้องเลื่อน (ขอบล่างช่องค้นหา ≤ 300px)
2. ชิ้นที่ตรงทุกข้อ: **2 แตะ** ทั้งทางรายการ (แตะแถว → บันทึก) และทางพิมพ์หา (พิมพ์ → แตะผลหรือ Enter → บันทึก)
3. เลือกห้องไว้แล้วเจอของที่ในระบบอยู่ห้องอื่น → แผ่นตรวจขึ้น "ที่ตั้งไม่ตรง" ให้เองโดยไม่ต้องเปิดฟอร์มเพิ่ม
4. บันทึกแล้วช่องค้นหาว่าง โฟกัสพร้อมพิมพ์ ตัวเลขขยับทันที และ**ไม่มีการโหลดทั้งรอบใหม่**
5. ผลของคนอื่นในรอบเดียวกันขึ้นภายใน 30 วินาทีขณะเปิดหน้าอยู่
6. ทำได้ครบเหมือนเดิม: นอกขอบเขต · ชิ้นส่วนย่อย · แก้ผลที่บันทึกแล้ว · ลิงก์ `?assetId=&mode=edit` · `returnTo` · รูปหลักฐาน + checklist รูปตามหมวด · คิวออฟไลน์ · อ่าน QR
7. `npm run verify` ผ่าน · ตรวจบนแอป dev ตามข้อ 8

**นอกขอบเขต** — หน้าสร้างรอบ · สแกนกล้องต่อเนื่อง · จำไฟฉาย/ซูม · เสียง · การพิมพ์ label · หน้ารายการค้าง/"หาไม่พบ" (นอกจากเพิ่มตัวกรองห้อง) · หน้าอนุมัติข้อไม่ตรง · ปุ่มเปลี่ยนรอบร่างเป็นเปิดตรวจ · เก็บศัพท์ไทยทั้งแอป (B3 — ข้อความใหม่ใน B2 เขียนเป็นไทย) · ไม่มี migration

## 2. แนวทาง

สร้างหน้าสแกนใหม่บนข้อมูลและ API เดิม · ลำดับการใช้งาน **ห้อง → รายการ/ค้นหา → แผ่นตรวจ → บันทึก** · ตรรกะทั้งหมดอยู่ในฟังก์ชันล้วน `src/lib/audit-scan-session.ts` (ทดสอบได้) · หน้าจอแตกเป็นคอมโพเนนต์หน้าที่เดียว · API บันทึก/ค้นหาเดิมแก้เท่าที่จำเป็น · เพิ่ม API ดึงความเปลี่ยนแปลง 1 ตัว

ไม่เลือก: แก้บนฟอร์มเดิม (ยังต้องเลือก "ตรง/ไม่ตรง" เอง ไฟล์และ state เดิมยังอยู่) · หน้า "เดินตรวจ" แยก (มี 2 หน้าคล้ายกันให้ดูแล)

## 3. หน้าจอและลำดับการใช้งาน

### 3.1 ส่วนบน (ทุกขนาดจอ)

- หัว: ← กลับ (`returnTo` เดิม) · ชื่อรอบ 1 บรรทัด · แถบความคืบหน้า + "ตรวจแล้ว X / Y · ไม่ตรง Z" — ตัวเลขของทั้งรอบ (ไม่ใช่เฉพาะห้อง) · ไม่ติดหัวจอ
- **ปุ่มห้อง** (`📍 <ที่ตั้ง> · <แผนก ถ้าเลือก>` + "เปลี่ยน ▾") · ยังไม่เลือก = เส้นประ "เลือกห้องที่กำลังตรวจ"
- **ช่องค้นหา** ติดหัวจอเมื่อเลื่อน (`sticky top-0`) · placeholder "พิมพ์รหัส ชื่อ หรือ Serial" · ปุ่มกล้องอยู่ขวาในช่อง · ปุ่ม × เมื่อมีข้อความ · `inputMode="search"` `enterKeyHint="search"` `autoComplete="off"`

### 3.2 แผ่นเลือกห้อง

- `Sheet` (ล่างบนมือถือ · ขวาบนจอใหญ่) · ค้นชื่อ/รหัสห้องได้
- แสดงเฉพาะที่ตั้งที่มีของในรอบ (จาก `expectedLocationId`) พร้อม "ยังไม่ตรวจ N / ทั้งหมด M" เรียงตามรหัส
- แผนก (ไม่บังคับ, ค่าเริ่ม "ทุกแผนก") — เลือกได้เฉพาะแผนกที่มีของในห้องนั้น
- "ไม่เลือกห้อง" ล้างค่า
- เก็บค่าผ่าน `audit-scan-context` เดิม (localStorage ต่อรอบ, รูป `{ locationId, departmentId }`) · เปลี่ยนห้องแล้วดึงความเปลี่ยนแปลงทันที (5.2)

### 3.3 รายการของห้อง (เมื่อช่องค้นหาว่าง)

- ตัวแบ่ง: **ยังไม่ตรวจ N · ตรวจแล้ว N · ทั้งหมด N** (ค่าเริ่ม "ยังไม่ตรวจ")
- เลือกห้องแล้ว: ของที่ `expectedLocationId` = ห้อง (และแผนกถ้าเลือก) · ไม่เลือกห้อง: ทั้งรอบ เรียงตามที่ตั้งแล้วรหัส และแต่ละแถวบอกห้อง
- แถว (ประมาณ 56px, แตะทั้งแถว): รหัส (หนา) · ชื่อ · ผู้ถือครองที่ควรเป็น · ป้ายด้านขวา: ไม่มี (ยังไม่ตรวจ) / "ตรวจแล้ว" / "ไม่ตรง" / "รอส่ง" (คิวออฟไลน์) · แท็บตรวจแล้วบอก "ตรวจโดย <ชื่อ> HH:mm"
- แสดงทีละ 50 แถว + ปุ่ม "แสดงเพิ่ม" (กัน DOM หนักในห้อง/รอบใหญ่)
- ท้ายแท็บ "ยังไม่ตรวจ": ลิงก์ "ของที่หาไม่เจอ → รายการค้าง" ไป `/audit/rounds/[id]/pending?locationId=<ห้อง>&returnTo=<หน้านี้>`

### 3.4 ผลค้นหา (เมื่อพิมพ์)

- ค้นในเครื่องจากของทั้งรอบ (ไม่จำกัดห้อง) · ฟิลด์: รหัส · ชื่อ · Serial · รหัสบัญชี · ชื่อผู้ถือครองที่ควรเป็น
- เริ่มเมื่อ ≥ 2 ตัวอักษร (นับ code point) · ไม่ค้นระหว่าง IME composition (แบบ B1)
- ลำดับ: ตรงทั้งคำกับรหัส/Serial/รหัสบัญชี → ขึ้นต้นด้วย → มีอยู่ · ภายในกลุ่ม ยังไม่ตรวจก่อน แล้วตามรหัส · สูงสุด 10 รายการ
- แต่ละแถว: รหัส · ชื่อ หรือ "Serial …" เมื่อตรงที่ Serial (ไฮไลต์ส่วนที่ตรง) · ป้าย: ห้องที่ควรอยู่ถ้าไม่ใช่ห้องปัจจุบัน ("อยู่ SNI_FL2") / "ตรวจแล้ว" / "ยังไม่ตรวจ"
- **Enter** = เปิดรายการแรก · ไม่มีผลในรอบ = ค้นทั้งทะเบียน (3.7)
- ไม่มีผลในรอบ: การ์ด "ไม่พบในรอบนี้ · ค้นในทะเบียนทั้งหมด" (แตะได้ · Enter ก็ทำ)

### 3.5 แผ่นตรวจ

- มือถือ/แท็บเล็ตแนวตั้ง: `Sheet side="bottom"` · ≥1024px: แผงขวาคงที่ข้างรายการ (2 คอลัมน์ รายการซ้าย)
- หัว: รหัส · ชื่อ · Serial · บรรทัดสถานะ: "ยังไม่ตรวจ" / "ตรวจแล้ว HH:mm โดย <ชื่อ> · กำลังแก้ผล" / "นอกขอบเขตรอบนี้"
- **4 ข้อ** แต่ละข้อ: ป้าย · ค่าจริงที่จะบันทึก · "ในระบบ: <ค่าที่ควรเป็น>" เมื่อต่างกัน · ปุ่ม "เปลี่ยน" → ตัวเลือกค้นหาได้ (`SearchableSelect` ส่วน A)
  - ที่ตั้ง · ผู้ถือครอง (มี "ไม่มีผู้ถือครอง") · แผนก · สภาพ
  - ข้อที่ต่างจากค่าที่ควรเป็น = พื้นเหลืองอ่อน + ป้ายตัวหนา (โทน warning)
  - **ข้อมูลล่าสุด**: ถ้าค่าปัจจุบันของทรัพย์สิน (ทะเบียน) ต่างจากค่าที่เก็บตอนสร้างรอบ → บรรทัดเล็ก "ข้อมูลล่าสุด: <ค่า>" ใต้ข้อนั้น (ผลตรวจยังเทียบค่าตอนสร้างรอบ)
- **ค่าเริ่มต้น** (ฟังก์ชันล้วน `buildCheckDefaults`)
  - ตรวจใหม่: ทุกข้อ = ค่าที่ควรเป็น ยกเว้น **ที่ตั้ง = ห้องที่เลือกไว้** ถ้าเลือก (แผนกไม่เติมตามห้อง)
  - แก้ไข (ของที่ `auditStatus` ไม่ใช่ `pending` — รวมที่คนอื่นตรวจ): ทุกข้อ = ค่าที่บันทึกไว้ (`actual*`) **ไม่เติมห้องปัจจุบันทับ**
  - นอกขอบเขต: ค่าจากทะเบียน ยกเว้นที่ตั้ง = ห้องที่เลือกไว้ถ้าเลือก
- **เปลี่ยนผู้ถือครองแล้วแผนกตาม**: ถ้ายังไม่ได้แก้แผนกเองในแผ่นนี้ ตั้งแผนก = แผนกของพนักงานคนนั้น (`Employee.departmentId`) · เลือก "ไม่มีผู้ถือครอง" ไม่เปลี่ยนแผนก
- "＋ หมายเหตุ / รูป" (พับไว้): หมายเหตุ · ถ่าย/แนบรูปได้หลายรูป (ชนิดไฟล์เดิมของฟอร์ม jpeg/png/webp/gif/avif/heic/heif · `capture="environment"`) · checklist รูปตามหมวด (ข้อมูลเดิม) เป็นคำแนะนำ
- "ชิ้นส่วนย่อย (N)" (พับไว้, แสดงเมื่อ N > 0): โหลดตอนเปิดแผ่น (5.3) · ต่อชิ้น: "ยืนยันพร้อมเครื่องหลัก" · "หาไม่เจอ" (dialog หมายเหตุ + รูป เดิม) · "ตรวจแยก" (เปิดแผ่นของชิ้นนั้น) · ความหมายและ API เดิม
- **ปุ่มเดียว** (ฟังก์ชันล้วน `diffCheckValues` นับข้อที่ต่างจากค่าที่ควรเป็น)
  - ไม่ต่าง: "บันทึก · ตรงทุกข้อ" (primary)
  - ต่าง N ข้อ: "บันทึก · ไม่ตรง N ข้อ (<ชื่อข้อ>)" (โทน warning)
  - แก้ไข: ขึ้นต้น "บันทึกการแก้ไข"
  - นอกขอบเขต: "บันทึกนอกขอบเขต" · ปิดปุ่มเมื่อมีข้อต่างแต่ยังไม่มีรูป (กติกาเดิม) พร้อมบอกเหตุผล
  - **กติการูปของการตรวจในรอบ (ผู้ใช้ตัดสินใจ 2026-10-07):** ปิดปุ่มเฉพาะเมื่อ "สภาพ" ไม่ตรงแต่ยังไม่มีรูป พร้อมบอกเหตุผล "สภาพไม่ตรง ต้องแนบรูปก่อนบันทึก" · ข้อไม่ตรงอื่น (ที่ตั้ง · ผู้ถือครอง · แผนก) ไม่บังคับรูป · ฟอร์มเดิมบังคับรูปทุกครั้งที่มีข้อไม่ตรง (ฝั่ง client เท่านั้น)
- รองลงมา: "ไม่ใช่ชิ้นนี้" = ปิดแผ่น กลับไปช่องค้นหา
- ส่ง `applyCorrections` เป็นค่าเดิมของผู้ใช้ (checkbox เดิมแสดงเฉพาะผู้มีสิทธิ์อนุมัติและไม่ติด SoD — ย้ายมาไว้ใต้ปุ่มบันทึก)

### 3.6 หลังบันทึก

- แผ่นปิด · ถ้าเปิดมาจากการค้นหา: ล้างช่องและโฟกัสช่องค้นหา · ถ้าจากรายการ: คงตำแหน่งเลื่อนเดิม
- แถบยืนยันใต้ช่องค้นหา (`role="status"`): "✓ <รหัส> บันทึกแล้ว · ตรงทุกข้อ" หรือ "· ไม่ตรง: <ข้อ>" + ปุ่ม "แก้" (เปิดแผ่นโหมดแก้ไข) · หายเมื่อเริ่มทำชิ้นถัดไป
- อัปเดตในเครื่องทันทีจากผลของ API (`applyScanResult`): สถานะชิ้น · ตัวเลขทั้งรอบ · ตัวเลขห้อง · ย้ายแถวไปแท็บตรวจแล้ว · **ไม่เรียก `router.refresh()`**
- `navigator.vibrate?.(30)` เมื่อบันทึกสำเร็จ (Android · iOS ไม่มีผล) · ไม่สั่นเมื่อผิดพลาด
- รูป: ส่งหลังบันทึกผลสำเร็จ · ส่งไม่ได้ → แถบ "บันทึกผลแล้ว แต่ส่งรูปไม่สำเร็จ · ส่งรูปอีกครั้ง" ส่งเฉพาะรูป (ไม่ POST ผลตรวจซ้ำ)

### 3.7 ค้นทั้งทะเบียนและนอกขอบเขต

- เรียก `scan-lookup` (5.3) ด้วยข้อความที่พิมพ์
- `in_round` → เปิดแผ่นของชิ้นนั้น · `out_of_scope` → การ์ด "<รหัส> ไม่อยู่ในขอบเขตรอบนี้" + "บันทึกนอกขอบเขต" → แผ่นโหมดนอกขอบเขต
- `candidates` (หาบางส่วนได้หลายชิ้น) → รายการไม่เกิน 5 แถว (บอกว่าในรอบหรือไม่) แตะแล้วค้นด้วย id แบบตรงอีกครั้ง
- `unknown_asset` → "ไม่พบรหัสนี้ในทะเบียน · ตรวจตัวสะกดหรือพิมพ์ Serial"
- ออฟไลน์ → "ค้นนอกรอบต้องใช้อินเทอร์เน็ต" (ไม่ใช่ "ไม่พบ") · lookup ผิดพลาดอื่น → ข้อความ error จริง ไม่ใช่ "ไม่พบ"

### 3.8 กล้อง (เฉพาะจุดเสียหนัก)

- ปุ่มในช่องค้นหา → แผงกล้องขึ้นใต้ช่องค้นหาและ `scrollIntoView` · ใช้ `startNativeAssetQrScanner` เดิม (`stopAfterSuccess: true` คงเดิม)
- อ่านได้ → ปิดกล้อง → lookup แบบเดิม → เปิดแผ่นตรวจ
- `NotAllowedError` → "ไม่ได้รับอนุญาตใช้กล้อง · เปิดสิทธิ์กล้องในการตั้งค่าเบราว์เซอร์ หรือพิมพ์ค้นหาแทน" · ไม่มีกล้อง → ข้อความเดิม
- ไฟฉาย/ซูมคงแบบเดิม (ไม่จำค่า)

### 3.9 ลิงก์เดิม

- `?assetId=<id>&mode=edit` → โหลดหน้าแล้วเปิดแผ่นของชิ้นนั้นทันที (โหมดแก้ไขถ้าตรวจแล้ว) · `returnTo` ใช้กับปุ่มกลับเหมือนเดิม · ชนิด `searchParams` ของหน้าคงเดิม

## 4. กรณีพิเศษ

| กรณี | พฤติกรรม |
|---|---|
| เลือกชิ้นที่ตรวจแล้ว (รวมคนอื่นตรวจ) | เปิดโหมดแก้ไข ส่ง `resultCorrection: true` · ไม่นับซ้ำโดยไม่รู้ตัว |
| หลายคนตรวจพร้อมกัน | ดึงความเปลี่ยนแปลงทุก 30 วินาทีขณะ `document.visibilityState === "visible"` · เมื่อกลับมาที่แอป · เมื่อเปลี่ยนห้อง · เมื่อบันทึกสำเร็จ · รวมเข้าข้อมูลในเครื่อง (`mergeStatusUpdates`) · แผ่นที่เปิดอยู่ไม่ถูกเปลี่ยนค่ากลางคัน แต่บรรทัดสถานะอัปเดตเป็น "เพิ่งถูกตรวจโดย <ชื่อ>" |
| ออฟไลน์ | บันทึกเข้าคิว IndexedDB เดิม · แถว "รอส่ง" · แถบ "ออฟไลน์ · รอส่ง N รายการ · ส่งตอนนี้" · **ส่งเองเมื่อ `online`** และหลังดึงข้อมูลสำเร็จ · คิวเก็บ 1 รายการต่อ `assetId` (ใหม่แทนเก่า) · ค้นในรอบยังใช้ได้ |
| ส่งคิวแล้ว server ปฏิเสธ (เช่น รอบถูกปิด) | รายการนั้นเป็น `failed` พร้อมข้อความ · ไม่ส่งรายการถัดไปซ้ำแบบวน · ปุ่ม "ลบออกจากคิว" |
| รอบถูกปิด/ยกเลิกระหว่างตรวจ | บันทึกได้ 400 → แถบแดง "รอบนี้ถูกปิดแล้ว บันทึกไม่ได้" + ลิงก์กลับหน้ารอบ |
| ชิ้นที่มีข้อไม่ตรงรออนุมัติแล้วแก้ผล | server ปิดข้อที่ไม่ไม่ตรงแล้ว และอัปเดตค่าข้อที่ยังไม่ตรง (5.4) |
| ของที่ย้ายหลังสร้างรอบ | บรรทัด "ข้อมูลล่าสุด" (3.5) |
| ไม่เลือกห้อง | ไม่เติมที่ตั้งให้ ไม่ขึ้นไม่ตรงเอง |

## 5. ฝั่ง server

### 5.1 หน้า `audit/rounds/[id]/scan/page.tsx`

- สิทธิ์ `audit:edit` · 404 เมื่อรอบไม่มี/ปิด/ยกเลิก (เดิม) · คง timing label `audit-scan.initial-data` และ `audit-scan.checklist-data`
- รายการต่อชิ้น (ไม่ include ชิ้นส่วนย่อยของทุกชิ้นแบบเดิม): `itemId` · `assetId` · `assetTag` · `name` · `serialNumber` · `fixedAssetCode` · `categoryId` · `expected{Location,Custodian,Department,Condition}Id` · `actual*Id` · `auditStatus` · `auditResult` · `lastScanAt` · `scannedByName` · ค่าปัจจุบันของทรัพย์สิน (`currentLocationId` · `custodianId` · `departmentId`) · `componentCount` (นับ `AssetComponent` ที่ `installed` และ `removedAt: null` ด้วย `groupBy` ครั้งเดียว)
- รายการกลางครั้งเดียว: ที่ตั้ง · แผนก · พนักงาน (`id`, `code`, `fullNameTh`, `departmentId`) · สภาพ · checklist รูปตามหมวด · สิทธิ์ `canApplyCorrections` · `serverTime`
- คง searchParams `{ returnTo, assetId, mode }`

### 5.2 API ใหม่ `GET /api/audit-rounds/[id]/scan-status?since=<ISO>`

- สิทธิ์ `audit:edit` (เดียวกับหน้า) · รอบปิด/ยกเลิกยังอ่านได้ (เพื่อให้หน้ารู้ว่ารอบปิดแล้ว) · `since` ไม่ถูกต้อง → 400
- คืน `{ serverTime, roundStatus, items: [...] }` — รายการที่ `updatedAt > since` (ทุกการเปลี่ยน: สแกน · หาไม่พบ · ยืนยันชิ้นส่วน) ฟิลด์เดียวกับ 5.1 ส่วนสถานะ (`itemId`, `auditStatus`, `auditResult`, `actual*Id`, `lastScanAt`, `scannedByName`)
- client ส่ง `since` = `serverTime` ของครั้งก่อน (ไม่ใช้นาฬิกาเครื่อง)

### 5.3 `POST /api/audit-rounds/[id]/scan-lookup`

- ตรงทั้งคำ (เดิม) ไม่เจอ → หาบางส่วน `contains` ใน `assetTag` · `serialNumber` · `fixedAssetCode` ของทรัพย์สิน `isActive` สูงสุด 5 → `{ status: "candidates", matches: [{ assetId, assetTag, title, inRound }] }` · ไม่เจอเลย → `unknown_asset` (เดิม)
- ข้อความ < 3 ตัว ไม่หาบางส่วน
- ผลแบบ `in_round`/`out_of_scope` เดิม (มี `components[]`, `installedIn[]`) ใช้โหลดชิ้นส่วนย่อยตอนเปิดแผ่นด้วย

### 5.4 `POST /api/audit-rounds/[id]/scan` (แก้ 2 ข้อ · สัญญา API อื่นคงเดิม)

- ในธุรกรรมเดียวกับการบันทึก: ข้อไม่ตรงของชิ้นนี้ที่ `reviewStatus: "pending"` และประเภทไม่อยู่ใน mismatches ใหม่ (ไม่รวม `not_found` ที่มีกติกาเดิม และประเภท component) → `reviewStatus: "rejected"` · `reviewRemark: "ยกเลิกเพราะแก้ผลตรวจ"` · `reviewedBy` = ผู้บันทึก · `reviewedAt` = เวลาบันทึก
- ข้อไม่ตรงที่ `pending` และประเภทยังไม่ตรง แต่ `actualValue` ต่างจากเดิม → อัปเดต `actualValue` และ `remark`
- เพิ่มใน response: `scannedByName`, `lastScanAt` (ให้ client รวมได้โดยไม่ต้องดึงใหม่)

### 5.5 หน้ารายการค้าง

- รับ `?locationId=` เพิ่ม (กรอง `expectedLocationId`) · ลิงก์จาก 3.3
