## 3. error จากเซิร์ฟเวอร์เป็นไทย

- **ไม่แก้ API**: ข้อความ error ของ API คงเดิม (ระบบอื่นที่เรียก API และโค้ดที่เทียบข้อความอยู่ เช่น หน้าสแกนเทียบ "Audit round is closed" ทำงานต่อได้)
- `src/lib/api-error-catalog.ts` (ล้วน · test import ได้): ตาราง `ข้อความอังกฤษ → key` เช่น `"Asset not found" → "assetNotFound"` และ `getApiErrorKey(raw): string | null`
- หมวดข้อความใหม่ `apiErrors` ใน `messages/th.json` และ `en.json` (en ใช้ข้อความอังกฤษเดิม)
- `useApiErrorMessage()` (client hook): คืนฟังก์ชัน `(raw?: string | null) => string`
  - รู้จัก → ข้อความไทยจาก `apiErrors`
  - ไม่รู้จักแต่มีข้อความ → "เกิดข้อผิดพลาด (ข้อความเดิม)"
  - ไม่มีข้อความ → `common.error`
- แก้หน้าจอที่แสดง `result.error`/`payload.error` ตรง ๆ (ราว 33 ไฟล์ใน `src/components`) ให้ผ่านตัวช่วยนี้ · ข้อความ `errors.*` ของหน้าซ่อมที่มีอยู่แล้วคงเดิม
- **test กันหลุด**: อ่านไฟล์ใน `src/app/api` และ `src/lib` หาข้อความ error อังกฤษ (`error: "…"`, `new Error("…")` ฯลฯ) ทุกข้อความต้องมีในตาราง และทุก key ในตารางต้องมีใน `apiErrors` ทั้งไทยและอังกฤษ

## 4. ภาษาของหน้าและปี พ.ศ.

- `<html lang>` = locale ที่เปิดอยู่ (`th`/`en`) โดยอ่านจาก next-intl ใน layout หลัก
- `src/lib/display-year.ts` (ล้วน): `toDisplayYear(gregorianYear, locale)` → th บวก 543 · en คงเดิม · `fromDisplayYear(value, locale)` แปลงกลับตอนกรอก
- ใช้ทุกที่ที่แสดงปีเดี่ยว ๆ เช่น "ปี 2026" ในหน้ารอบตรวจนับ ภาพรวม coverage และตัวกรองปี
- ช่องปีของฟอร์มรอบตรวจนับ: หน้าไทยแสดงและรับ พ.ศ. (ค่าเริ่ม 2569) ป้าย "ปีตรวจนับ (พ.ศ.)" · บันทึกเป็น ค.ศ. เหมือนเดิม (ไม่แก้ข้อมูลเก่า ไม่มี migration) · รับค่า พ.ศ. 2500–2700
- วันที่ที่จัดรูปแบบด้วย `th-TH` เป็น พ.ศ. อยู่แล้ว — ตรวจว่าไม่มีที่ไหนแสดงปี ค.ศ. ปนในหน้าไทย
- ข้อยกเว้น: รหัสที่มีปีในตัว (AUD-2026-0002, GRL-COM-24-…) · บรรทัด © หน้า login · ปฏิทินของ `<input type="date">` (ตามการตั้งค่าเครื่อง)

## 5. ล้างข้อความที่ไม่ใช้แล้ว

- สคริปต์ `scripts/find-unused-messages.mjs` หา key ที่ไม่พบเป็นข้อความในโค้ด (ทั้งชื่อเต็ม ชื่อท้าย และ prefix ของ key ที่ประกอบตอนรัน) — เป็นเครื่องมือช่วย ไม่ใช่ตัวตัดสิน
- ตรวจทีละหมวด: หมวดที่ประกอบ key ตอนรัน (เช่น `systemLogPage` ใช้ `actions.${…}`) ต้องหาค่าที่เป็นไปได้จากโค้ด/ข้อมูลก่อนลบ
- ลบเฉพาะที่ยืนยันแล้ว ทั้ง th และ en · รายงาน key ที่ลบทั้งหมดในรายงานของงาน
- test ใหม่ `tests/messages-parity.test.ts`: th และ en มีชุด key ตรงกันทั้งไฟล์ (ตอนนี้ตรงกัน 4,136/4,136)

## 6. กันคำเก่ากลับมา

- `tests/thai-glossary.test.ts` อ่านข้อความไทยทุก key แล้วไม่ผ่านถ้าเจอคำเลิกใช้ (ข้อ 2.1–2.2)
  - ข้อยกเว้นระบุเป็นรายการชัดเจน (เช่น "พื้นที่จัดเก็บไฟล์" · คำเทคนิคในหมวดผู้ดูแลระบบ) พร้อมเหตุผลในโค้ด test
  - เปิดตรวจทีละหมวด: งานแรกสร้าง test โดยตรวจเฉพาะหมวดที่แก้แล้ว แต่ละงานแก้คำเพิ่มหมวดของตัวเองเข้า list · งานสุดท้ายของกลุ่มคำเปลี่ยนเป็นตรวจทุกหมวด
- ข้อความไทยที่เขียนตรงในโค้ด: แก้ตามคำศัพท์กลางเฉพาะที่ผู้ใช้เห็น (ชื่อการเคลื่อนไหว ข้อความแจ้งเตือน กล่องงาน ค่าตั้งต้นแม่แบบแจ้งเตือน) · ชื่อคอลัมน์นำเข้า Excel **เพิ่มคำใหม่และคงคำเก่าเป็นชื่อเรียกแทน** (ไฟล์ที่ใช้อยู่ยังนำเข้าได้)
