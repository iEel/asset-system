**Rules:**
- **POST and PUT** write `note` into the `SystemLog` `newValue`.
- **Reactivation (PUT):**
  - The trigger is `existing.isActive === false`, `input.isActive === true`, the role is not a system role, and the
    actor is not `system_admin`.
  - In that case, every permission the role will hold must be in the actor's permissions.
  - Otherwise return 403 with `"Forbidden: cannot activate a role with permissions you do not hold"`.
  - Add the catalog key `activateRoleForbidden`, Thai "เปิดใช้งานบทบาทที่มีสิทธิ์ที่คุณไม่มีไม่ได้".
- **`POST .../users`:**
  - Needs `user:edit`.
  - A role that does not exist returns 404.
  - An inactive role returns 400 `"Role is inactive"`. Catalog key `roleInactiveForAdd`, Thai
    "บทบาทนี้ปิดใช้งานอยู่ เพิ่มผู้ใช้ไม่ได้".
  - For each distinct id:
    - Load the user with `userAccessInclude`. A missing or inactive user is refused with `"User not found or inactive"`.
    - A user who already holds the role is skipped silently (it counts as added: no write).
    - Run `getUserAccessChangeError` with `requestedRoleIds = stored + roleId`, `currentRoleIds = stored`,
      `nextIsActive: true` and `otherActiveSystemAdminCount` from `countOtherActiveSystemAdmins`.
    - If it is refused, record the reason.
    - Otherwise create the `userRole` and log `module:"user"`, `action:"update"`, `recordId:userId`,
      `oldValue.roleIds`, `newValue.roleIds` and `newValue.note`, then call `invalidateUserAccess(userId)`.
  - After the loop, if any were added, write one role log: `module:"role"`, `recordId:roleId`, `action:"update"`,
    `newValue:{ addedUserIds, note }`.
