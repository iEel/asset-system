## Rulings made while planning

- **P2-R1 (one department helper, recon critic C2):** `getRegisterDepartment` in `src/lib/asset-department-rule.ts` serves create, edit and the form lock; the transfer helpers are not reused for the edit (they read a null new holder as "unchanged", and a cleared holder must free the department). Holder unchanged on บุคคล/Stock = the automatic fix (no reason); skipped while a handover is open.
- **P2-R2 (holder types):** a holder may be set on บุคคล, ส่วนกลาง, Stock (the types checkout allows) and License (its assignee, as today). Changing the ownership type keeps the holder, except a change to ส่วนควบ, which clears it on the client. The server adds no refusal for a component holder (components take the parent's holder through the sync).
- **P2-R3 (open handover, spec §7.3 and decision 10):** holder, room **and department** are read-only while an HO- is open, because the server lock refuses all three. The notice links to the handover document (where it can be cancelled) and **not** to โอนย้าย: transfer refuses an asset with an open handover (`asset-operation-eligibility.ts:146`). Plan 1's `asset.transactionReasonOpenCheckoutCorrection` is reworded the same way. The custody lock compares the department the server computes, not the one the client sends.
- **P2-R4 (reason):** the PUT body carries `correctionReason` (trimmed, max 500). It is required when the user changes the room, the holder, or the department (not the automatic fix); the field sits in the ข้อมูลหลัก card under those rows (id `asset-correction-reason`) and its text is repeated in the change list, so focus and errors reach it (spec §7.3 put it in the change list only). The custody lock (409) runs before the reason check (400).
- **P2-R5 (history rows):** one `referenceId = randomUUID()` per save, `referenceType: "register_edit"`. Room, holder and department write `register_*_correction` with the reason (the automatic fix: reason null). The 14 fields of §7.4 write one `register_field_correction` each, from/to a JSON snapshot `{"<column>": value}` of at most 500 characters (the value is cut first). Ownership type is one of the 14, so `ownership_type_change` stops being written (it moves to the labels' "older" list). A tag change writes `asset_tag_change` with the plain old and new tag (plan 6 compares it with the last print). Status, condition and License changes keep their types. Written types 50 → 51, labelled 54 → 56. The dashboard feed leaves out `register_field_correction`.
- **P2-R6 (the tag):** the "เปลี่ยนรหัส" dialog only sets the form's tag; the one PUT saves it. No new route.
- **P2-R7 (isActive):** the checkbox leaves the form; PUT ignores `isActive`; POST always writes `isActive: true`. API bodies that still send `isActive: true` keep working.
- **P2-R8 (POST):** asset, first movement and audit in one transaction (`writeAuditLog(tx, …)`), wrapped in `withPrismaUniqueRetry` only when the tag was generated; a typed tag that loses the race answers `fieldErrors: { assetTag: "duplicate" }`. The holder is read active (`checkoutReceiverInactive` under `custodianId` otherwise).
- **P2-R9 (E2E TR2):** POST now gives a held บุคคล asset its holder's department, so `transfer.spec.ts` TR2 can no longer seed an old mismatch. TR2 seeds the held asset normally and checks a room-only transfer (one change, department locked to the holder's); the mismatch path stays covered by `tests/transfer-rules.test.ts` and a UAT line on Production data.
- **P2-R10 (stale save):** PUT claims the row on the values it read (as plan 1), not on what the page loaded; a second editor's save still overwrites, and both are in history.
- **P2-R11 (sections):** create and edit share one layout: the required card (create "ข้อมูลที่ต้องกรอก", edit "ข้อมูลหลัก"), License seats unfolded for License, then folded: ติดตั้งเป็นส่วนควบ (create only), การจัดซื้อและประกัน, **เอกสารจัดซื้อ (its own section, open, content unchanged until plan 3)**, รูปทรัพย์สิน, รายละเอียดเฉพาะทรัพย์สิน (custom fields), ข้อมูลอื่น ๆ และขั้นสูง (remark, JSON). The ownership type is a `Segmented` from 768 px and the native `#asset-ownership-type` select below, one rendered at a time (`useMediaQuery`).
